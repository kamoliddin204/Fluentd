Docker Postgres Logs

Overview​

In this documentation we are going to learn how to collect Docker logs and PostgreSQL logs and convert them to single format. Today we're going to convert json format. The final result will be written to a file.

How It Works​

The fluentd configuration collects logs from PostgreSQL and Docker containers, unifies them, and writes to a single file.

  • Sources PostgreSQL Logs:
    • Collected from /var/log/postgresql/postgresql.log.
    • Docker Logs: Collected from /var/lib/docker/containers/*/*.log.
  • Transformation Each log is:
    • Tagged (postgres.log or docker.log)
    • Enriched with a source field
    • Normalized to a unified message field.
  • Output
    • Logs are:
      • Shown in real-time via stdout
      • Appended to /var/log/merged_logs/merged.log in JSON format.
  • Position Tracking
    • Fluentd uses position files to avoid duplicate logs and track read progress.

Reading Docker and PostgreSQL logs​

<source>
  @type tail
  path /var/log/postgresql/postgresql.log
  pos_file /fluentd/positions/postgresql.pos
  tag postgres.log
  format none
</source>

<source>
  @type tail
  path /var/lib/docker/containers/*/*.log
  pos_file /fluentd/positions/docker-container.log.pos
  tag docker.log
  format json
</source>

<filter postgres.log>
  @type record_transformer
  <record>
    source postgres
    message ${record["message"] || record["log"] || record["msg"]}
  </record>
</filter>

<filter docker.log>
  @type record_transformer
  <record>
    source docker
    message ${record["log"] || record["message"] || record["msg"]}
  </record>
</filter>

<match **>
  @type copy
  <store>
    @type stdout
  </store>
  <store>
    @type file
    path /var/log/merged_logs/merged.log
    append true
    format json
  </store>
</match>

path - PostgreSQL log file will be read from this specific path

pos_file - It is used to keep track of the last read line for log recumption

tag - Tags each event as postgres.log

format none - Means the log are read as plain text (one line = one record)

format json - Since docker logs are stored as JSON (with fields like log, time, stream, etc.)

<filter postgres.log> - Applies a filter only to log tagged postres.log

source postgres - Adds a new field called source with value postgres

message - Ensures the final message field is normalized- it tries to pull from:

  • message
  • log
  • msg

This amkes compitable with multiple logging formats

Docker Logs is the same as above. Set source to Docker

Normalize the message field from any available source (log, message or msg)

Coming to match section it matches all logs (using ** wildcard)

It copies each log to multiple destinations:

  • Console (stdout) - useful for debuging and testing
  • file - writes all logs to a file in Json format:
    • File: /var/log/merged_logs/merged.log
    • Appends to the file rather than overwriting it.

How to run with Docker​

You can run this Fluentd configuration in a Docker container using the following steps:

Project structure:​

Fluentd_Task/
├── fluent.conf
│ 
├── docker/
│   ├── test-container.log
│ 
├── positions/
│   ├── docker-container.log.pos
│   ├── postgresql.log
│ 
├── merged_logs/merged.log
│   ├── 
│   
├── postgresql.log

Docker run command:​

docker run -d --name fluentd-log-aggregator `
>>   -v "C:\Users\User\Desktop\Task_2\fluent.conf:/fluentd/etc/fluent.conf" `
>>   -v "C:\Users\User\Desktop\Task_2\postgresql.log:/var/log/postgresql/postgresql.log" `
>>   -v "C:\Users\User\Desktop\Task_2\docker:/var/lib/docker/containers" `
>>   -v "C:\Users\User\Desktop\Task_2\merged_logs:/var/log/merged_logs" `
>>   -v "C:\Users\User\Desktop\Task_2\positions:/fluentd/positions" `
>>   -p 9880:9880 `
>>   fluent/fluentd:edge

docker run - Launches a new docker container

-d - "detached mode": it runs the container in a detached mode (in the background)

--name fluentd-log-aggregator - Name which is given to container by user (fluentd-log-aggregator)

-v "C:\Users\User\Desktop\Task_2\fluent.conf:/fluentd/etc/fluent.conf" - It mounts your custom Fluentd configuration file from the host machine into the container.

  • Lest side = path on your host.
  • Right side = where Fluentd expects the config file inside the container (/fluentd/etc/fluentd.conf)

-v "C:\Users\User\Desktop\Task_2\postgresql.log:/var/log/postgresql/postgresql.log" - It mounte the postgreSQL log file from your host to the container. Fluentd will read PostgreSQL logs from this location inside the container.

-v "C:\Users\User\Desktop\Task_2\docker:/var/lib/docker/containers" - It mounts the Docker container log directory into the container. Fluentd can now access all container logs, which are stored under /var/lib/docker/containers.

Note: This only works if your Docker containers use the json-file log driver

-v "C:\Users\User\Desktop\Task_2\merged_logs:/var/log/merged_logs" - It mounts s host directory where merged and normalized logs can be written (optional). If fluentd configured to output logs to file, this is where they will be stored.

-v "C:\Users\User\Desktop\Task_2\positions:/fluentd/positions" - It mounts the directory where Fluentd stored position tracking files. These files track the last read line in each log file, so Fluentd doesn't reporcess logs after restart.

-p 9880:9880 - It exposes port 9880 from the container to the host. This is useful if you've enabled HTTP input plugin or want to interact with Fluentd over HTTP.

fluent/fluentd:edge - The Docker image being used is fluent/fluentd:edge :edge is the last (edge or development) version of Fluentd `

Log samples​

Docker Log sample (Raw)​

Docker stores logs in JSON format by default. Here's What a typical raw log from a Docker container looks like:

{
  "log": "User created successfully\n",
  "stream": "stdout",
  "time": "2025-08-04T04:25:10.123456789Z"
}

PostgreSQL Log sample (Raw)​

A raw PostgreSQL log line might look like this:

2025-08-04 04:26:45 [INFO] connection received: host=172.18.0.1 port=5432

After filtering and parsing the final result look like this:​

{
  "time": "2025-08-04 04:26:45",
  "level": "INFO",
  "message": "connection received: host=172.18.0.1 port=5432"
}
